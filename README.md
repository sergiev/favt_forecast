# Прогноз ограничений аэропортов РФ

Вероятность, что аэропорт X в момент Y будет открыт, работать «по согласованию» или не принимать и не выпускать рейсы. Горизонт 14 суток, шаг 1 час. Единственный источник — публичная лента [Говорит Росавиация](https://t.me/s/favt_info). Это не NOTAM и не метеосводка.

Команды запускаются из этой папки.

## Запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```text
uv sync
uv run favt-forecast sync
uv run favt-forecast serve
```

`sync` первый раз выкачивает архив канала, разбирает посты и обучает модель. Дальше он дочитывает только новые сообщения и переобучается, если набор событий изменился. Интерфейс: http://127.0.0.1:8787

Если порт занят: `uv run favt-forecast serve --port 8791`.

Сервер при старте и затем каждые 3 минуты сам добирает ленту. В интерфейсе это переключатель «автодолив» и кнопка «Долить сейчас».

Точечный запрос из консоли. Время без зоны считается как МСК.

```text
uv run favt-forecast predict --airport SVO --at 2026-11-05T03:30
```

`--airport` принимает IATA, ICAO или русское название. Без `--at` печатается почасовой прогноз.

Остальные команды:

```text
uv run favt-forecast sync --new-only
uv run favt-forecast sync --offline
uv run favt-forecast train
uv run favt-forecast backtest
uv run favt-forecast selftest
```

`--offline` заново разбирает уже скачанные тексты и не ходит в сеть. База и веса лежат в `data/`.

Обучение идёт на GPU, если CatBoost его видит. Иначе CPU. Принудительно: переменная окружения `FAVT_DEVICE=CPU` или `GPU`.

## Что считается состоянием

Пост канала превращается в событие только если это ввод, снятие или режим «по согласованию». Цитата чужого поста не задаёт действие. Сводки происшествий и рубрика `#аэровыходные` отбрасываются.

| Состояние | Откуда в тексте |
| --- | --- |
| `CLOSED` | введены ограничения на приём и выпуск |
| `RESTRICTED` | рейсы по согласованию с органами |
| `OPEN` | ограничения сняты |

Из событий собираются интервалы. Если после закрытия нет сообщения о снятии, интервал обрывается через 24 часа и помечается как домысленный. Часы в тексте (`с 01:00 МСК`) важнее времени публикации.

На тепловой карте слева 7 суток такого факта, справа 14 суток прогноза. На линейном графике только прогноз.

## Как получается вероятность

Закрытие порождается внешним решением, которого в ленте нет. Поэтому модель не предсказывает причину. Она оценивает, насколько текущий режим и местная история похожи на прошлые часы.

Два контура CatBoost, оба на три класса:

- ближний, до 36 часов: текущее состояние, сколько оно уже длится, кривая длительности прошлых закрытий этого аэропорта, доля закрытых соседей в радиусах 250, 500 и 1000 км и в том же кластере;
- дальний, от 12 часов до 14 суток: суточный и недельный цикл, доля закрытий за 7, 14 и 30 суток, прайор «этот аэропорт в этот час суток».

На участке 18–36 часов вероятности двух контуров смешиваются. Прайор — экспоненциально затухающая частота состояния в данный час суток, отдельно за 14 и за 60 дней. Он же запасной ответ, если деревьев ещё нет.

Вероятности калибруются на последних 14 сутках меток: температура, затем изотоника, если она не ухудшает logloss. Если на этой проверке прайор точнее деревьев, ответы смешиваются. Метрики печатает `backtest`.

Один запрос на 14 суток — доли секунды. Полное обучение после долива — десятки секунд.

## Чего модель не знает

На 12–14 сутках локальный импульс уже затух. Остаётся климатология: ночь и ранее утро опаснее дня, у части аэропортов базовый уровень выше. Это не прогноз конкретного внешнего триггера.

Короткое закрытие между часовыми точками может не попасть в клетку: метка — состояние на начало часа. Аэропорт без кода IATA показывается кодом ICAO. «Утренний» в сводках без устойчивого кода в справочнике отдельно не ведётся.
